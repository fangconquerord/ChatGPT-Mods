# Prompt Compiler

Prompt Compiler — локальный детерминированный движок GPT Mods для улучшения промтов. Он не использует нейросети, модели, API, серверы, телеметрию или динамически загружаемый код. Движок применяет проверяемые правила и эвристики; он не «понимает» язык так, как это делает языковая модель.

## Публичный интерфейс

После загрузки content scripts доступен единый синхронный метод:

```js
const result = globalThis.GPTModsPromptCompiler.enhancePrompt({
  text: "Сравни V9 Pro и V9 Turbo+.",
  locale: "ru",
  context: [
    { role: "user", content: "Нужны практические различия." }
  ]
});
```

Результат содержит исходный и итоговый текст, `changed`, действие `unchanged`, `rewritten` или `clarify_then_answer`, язык, основное и дополнительные намерения, уверенность, уточняющие вопросы, сохранённые фрагменты, применённые ID правил, предупреждения и метрики. JSDoc-контракт находится в `types.js`. Режимов интенсивности нет: лучший вариант выбирается автоматически.

## Архитектура и конвейер

Модули подключаются в порядке, заданном в `manifest.json`:

1. `rules-bundle.js` предоставляет локальную копию JSON-правил без runtime-запросов к файлам.
2. `validation.js` проверяет тип, пустоту, размер и повреждённые управляющие данные.
3. `protection.js` заменяет код, команды, пути, URL, числа, даты, версии и другие значимые значения уникальными токенами.
4. `normalization.js` безопасно нормализует только незакрытый текст.
5. `language.js` определяет русский или английский с учётом смешанного технического текста.
6. `segmentation.js` выделяет предложения, списки, команды, вопросы, ошибки и ограничения.
7. `classifier.js` взвешивает сильные, положительные, слабые и отрицательные триггеры всех намерений.
8. `extraction.js` извлекает объекты сравнения, продукты, языки, платформы, форматы, числа и ограничения.
9. `context.js` осторожно рассматривает только последние явные пользовательские сведения и не переносит предположения ассистента.
10. `ambiguity.js` сверяет критические и полезные слоты и формирует не более трёх вопросов.
11. `planner.js` выбирает совместимые смысловые модули и динамический предел роста.
12. `synthesis.js` выводит предметный профиль из формулировки, сущностей и типа задачи, выбирает детерминированные варианты фраз и собирает интегрированную постановку без универсального хвоста требований. Для image-промтов он распознаёт уже названный объект, подбирает стиль-зависимые детали качества и формирует совместимые негативные ограничения.
13. `renderer.js` оформляет синтез как цельный промт; список появляется только для действительно необходимых уточнений или сложной структуры.
14. `candidates.js` строит нормализованный исходник и несколько содержательно разных стратегий переформулировки.
15. `scoring.js` оценивает сохранность, отвечаемость, предметную конкретику, интеграцию, структуру и краткость, не вознаграждая количество шаблонных пунктов само по себе.
16. `validation.js` отбрасывает варианты с потерянными токенами, ограничениями, запрещёнными фразами, дублями или чрезмерной длиной.
17. `pipeline.js` восстанавливает фрагменты дословно и безопасно возвращает исходник, если улучшенный вариант не прошёл проверку.

Нормализованный исходник всегда участвует в рейтинге и может победить. Тексты, уже созданные компилятором, распознаются для идемпотентного повторного запуска.

## Правила и схемы

Исходные данные находятся в `rules/`:

- `intents.json` — 39 профилей намерений с RU/EN-триггерами, слотами и ссылками на модули;
- `modules.json` — 115 различных смысловых модулей;
- `slot-schemas.json` — критические, полезные и необязательные слоты для каждого намерения;
- `aliases.ru.json`, `aliases.en.json` — языковые маркеры, синонимы, разговорные формы и частые опечатки;
- `protected-patterns.json` — ограниченные декларативные регулярные выражения;
- `ambiguity-rules.json` — локализованные вопросы для отсутствующих критических слотов;
- `bypass-rules.json` — случаи, которые нельзя раздувать;
- `validation-rules.json`, `banned-fluff.json` — ограничения качества и запрещённые усилители;
- `output-structures.json`, `domain-rules.json` — структуры и правила предметных областей.

JSON Schema расположены в `schemas/`. Runtime-валидатор дополнительно проверяет уникальность ID, ссылки, локализации, веса, диапазоны, регулярные выражения и циклы зависимостей.

`npm run generate:rules` читает все JSON-файлы, вычисляет общий SHA-256 и создаёт `rules-bundle.js`. Этот файл хранится в расширении, поэтому Chrome не делает даже локальный `fetch`; сборка повторно генерирует bundle и включает исходные JSON и схемы в `dist`.

## Расширение правил

### Новое намерение

1. Добавьте профиль со стабильным уникальным `id` в `rules/intents.json`.
2. Заполните осмысленные RU/EN-триггеры, слоты, совместимые модули и параметры уверенности.
3. Добавьте одноимённую запись в `rules/slot-schemas.json`.
4. Добавьте RU/EN-классификационный и golden-тест.
5. Выполните `npm run generate:rules && npm test`.

### Новый модуль

Добавьте запись в `rules/modules.json`: локализованный текст, допустимые и запрещённые намерения, условия активации и деактивации, вес, стоимость длины, конфликты, зависимости и ключ дедупликации. Затем свяжите ID с нужным намерением. Строки JSON никогда не исполняются как JavaScript.

### Новый язык

Добавьте словарь aliases и локализации триггеров, модулей и вопросов. Затем расширьте `language.js` и генератор bundle явным ключом. Новый язык должен иметь отдельные классификационные, защитные и golden-тесты; английский fallback не считается полной поддержкой языка.

## Безопасность и приватность

- пользовательский промт остаётся в content script и не сохраняется;
- в коде компилятора нет `fetch`, XHR, WebSocket, `eval` или `new Function`;
- регулярные выражения централизованно компилируются после проверки длины, флагов и запрещённых конструкций;
- количество совпадений, сообщений контекста, кандидатов и размер входа ограничены;
- пользовательский код и команды никогда не исполняются;
- при исключении UI оставляет исходный текст в поле;
- замена использует события поля ChatGPT и сохраняет штатную отмену через `Ctrl+Z`.

## Проверки и сборка

```bash
npm install
npm run generate:rules
npm run typecheck
npm run lint
npm test
npm run test:integration
npm run benchmark
npm run build
npm run package
```

Тесты используют встроенный `node:test`, поэтому runtime-зависимостей нет. Benchmark выполняет 1000 компиляций и завершается ошибкой, если p95 превышает 50 мс. `build` создаёт готовую папку `dist`, а `package` — ZIP в `release/`.

## Интеграция с GPT Mods

`content-prompt-enhancer.js` отвечает только за поиск composer, кнопку, состояния UI и корректную замену текста. По нажатию он вызывает `GPTModsPromptCompiler.enhancePrompt`, не отправляет сообщение автоматически и показывает безопасную ошибку без потери черновика. Фича по-прежнему включается единственным переключателем «Улучшение запроса».

## Реальные ограничения

Правила надёжно покрывают известные формулировки, но не дают универсального семантического понимания. Необычная метафора, редкий язык, сложная кореференция или намеренно двусмысленный текст могут быть классифицированы неточно. Защита вложенных форматов консервативна: сложные вложенные JSON/XML лучше передавать в fenced code block. Контекст используется только при однозначной ссылке и никогда не превращает предположение ассистента в требование пользователя.
